01 The Two-Account Loop
  1. Create two accounts. A = attacker, B = victim. Same plan + cross-tenant if possible.
  2. Populate distinctively. Different names, files, settings. Visible deltas = fast confirmation.
  3. Use B normally. Walk every feature. Capture in Burp/Caido.
  4. Swap to A's session. Replay B's requests with A's token/cookie.
  5. Confirm. Success = A retrieves/mutates B's data.
Burp Match & Replace auto-swaps the Authorization header. Autorize automates the entire loop.
02 Per-Endpoint Method Matrix
  • GET   reads victim data?
  • POST   create resources under victim?
  • PUT / PATCH   mutate victim fields (email, role, reset token)?
  • DELETE   delete victim resources?
  • HEAD   existence probe / header leakage?
  • OPTIONS   CORS preflight reveals hidden methods?
  • FOO   bogus method falls through to GET on some frameworks

08 Endpoint Variants to Try
  • Version downgrade   v3 → v2 → v1 → internal → legacy
  • Mobile-only   /api/mobile/, /api/ios/, /api/android/
  • Subpath swap   /profile → /details, /info, /summary
  • Batch / list   ?ids[]=7011, /users/batch
  • Export / report   /export, /print, /pdf, /download
  • Content-type swap   json → xml → form-data → urlencoded
09 GraphQL Quick Reference
Introspection first. Then test every resolver with foreign IDs.
# Alias-batched IDOR — 1 HTTP req, N records query { u1: user(id: 7001) { email phone } u2: user(id: 7002) { email phone } // ... 100+ aliases ... u100: user(id: 7100) { email phone } }
  • Field-level auth gaps   check nested resolvers (user.orders, user.paymentMethod)
  • Mutations   updateUser, resetPassword, transferOwnership with foreign IDs
  • Hidden mutations   introspection reveals admin ops accessible to low-priv
  • Batch ops   array of operations in one POST
10 Advanced & Chains
  • IDOR → ATO   mutate victim's email, trigger reset, take over
  • IDOR + IDOR   first leaks the second's required identifier
  • IDOR + mass assignment   add role, tenant_id, is_admin in body
  • IDOR + race   non-atomic ownership check; HTTP/2 single-packet
  • IDOR + cache deception   personalized response cached publicly
  • WebSocket IDOR   replay frames with foreign resource_id
  • Mobile-backend   APK decompile + Frida pin-bypass for endpoints
  • UUIDv1 prediction   guidtool, predict from one sample

12 AI-Assisted Workflow (2026)
  • use AI   extract endpoints from JS bundles & OpenAPI
  • use AI   scaffold safe PoC scripts (hard-cap N=5)
  • use AI   draft report structure & CVSS reasoning
  • careful   bypass-payload brainstorming (verify each)
  • manual   the two-account confirmation loop
  • manual   deciding a bug exists
  • never   paste victim PII / live tokens to AI providers
Pattern: 2 different models — one finds, one disproves. Glasswing-style.
13 Report Structure
  1. Summary   one sentence, name the endpoint & parameter
  2. Severity   CVSS v3.1 vector with reasoning
  3. Steps to Reproduce   both accounts, both tokens (redacted), exact request
  4. PoC   2 screenshots min; script ≤ 5 records
  5. Impact   quantify (n users, PII scope, cross-tenant?)
  6. Remediation   brief; request.user.id == params.user_id

16 Pre-flight Checklist
  • Two accounts live & populated
  • Burp + Autorize, second token configured
  • Swap ID in every location (path / query / body / header / cookie)
  • Swap method (every verb, not just GET)
  • Try path-normalization variants on blocked endpoints
  • Try header-injection bypasses on blocked endpoints
  • Try array / object / type-confused parameter shapes
  • For UUID/random IDs: hunt where they leak publicly
  • GraphQL?   introspect → alias → nested → mutations
  • Found one?   check the chain (ATO / mass / cross-tenant)
  • Cap PoC at 5 records, never dump database
  • Re-read scope before reporting
Scope discipline: Every technique on this card applies only to systems whose owners have explicitly authorized testing — bug bounty programs, VDPs, or written engagements. Out-of-scope testing is unauthorized access.
